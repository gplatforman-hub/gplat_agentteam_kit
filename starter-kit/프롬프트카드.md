```

  2. 날짜
  3. ⭐ 메모 파일 또는 붙여넣은 메모 ← 이게 없으면 시작하지 않는다
  4. 참석자 (이름 대신 역할로 적어도 된다)
  5. 이 회의록을 누구에게 돌리는지

[회의록 구조]
1. 회의명 · 일시 · 참석(역할)
2. 한 줄 요약
3. 논의 — 주제별로 2~4줄
4. ⭐ 결정사항 — 번호 목록
5. ⭐ 할 일 표 — 할 일 | 담당 | 기한 | 상태
6. 미결·다음 회의에서 볼 것
7. 확인 필요 — 메모만으로는 알 수 없는 것 모음

- 문장은 짧게. 한 항목 한 줄.
- 논의만 하고 정하지 않은 것은 결정사항에 올리지 않는다. "미결"로 둔다.
- 할 일에 담당이나 기한이 없으면 지어내지 말고 "확인 필요"로 둔다.
- 메모에 숫자가 있으면 숫자 그대로 쓴다.

[절대 금지]

- 실제 동료 이름·연락처를 결과물에 넣지 않는다. 역할이나 이니셜로 바꾼다.
- 회의록을 직접 메일로 보내지 않는다. 요약 메일 본문은 초안까지만.

[저장]
workspace/결과물/<날짜>_<회의명>_회의록.md

[기존 스킬 처리 — 이 줄을 빼면 스킬이 두 개가 된다]
- 같은 일을 하는 스킬이 .claude/skills/ 에 이미 있으면 (이름이 비슷한 다른 스킬 포함)
  새로 만들지 말고 그 폴더의 SKILL.md 를 이 내용으로 통째로 덮어쓴다.
- 폴더 이름이 다르면 이 이름으로 폴더를 바꾸고, 옛 폴더는 .claude/skills/_보관/ 으로 옮긴다.
- 덮어쓴 뒤 .claude/agents/ 의 직원 파일에서 이 스킬을 가리키는 줄을 찾아
  새 이름과 맞는지 확인하고, 안 맞으면 고친다.
- 무엇을 옮기고 무엇을 고쳤는지 마지막에 목록으로 알려준다.

[트리거]
"회의록", "회의 정리", "회의 메모", "녹취 정리", "결정사항", "할 일 정리"
```

## 망가졌을 때

| 증상 | 먼저 해 볼 것 |
|---|---|
| 결과가 이상함 | 결과를 손으로 고치지 말고 무엇이 틀렸는지 말해서 다시 시키기. 같은 지적이 반복되면 스킬을 고치기(P5-c) |
| 아까 상태로 돌리고 싶음 | "git log --oneline -10 보여 주고, [파일이름] 을 아까 저장 지점으로 되돌려 줘" |
| 스킬이 안 불림 | `/스킬이름` 으로 직접 부르기. 폴더 이름·name 이 영어 소문자인지 확인 |
| 슬랙이 조용함 | `자동시작_켜기.bat` 더블클릭. 그래도면 "`py 점검.py 8` 실행해 줘" |
| 서버를 다시 켠 직후 대답이 없음 | 10~20초 기다렸다가 다시 (켜지는 중) |
| 점검은 ❌ 인데 슬랙은 대답함 | 킷이 옛 버전. 파워셸에 `irm https://raw.githubusercontent.com/gplatforman-hub/gplat_agentteam_kit/main/update.ps1 \| iex` (내 직원·스킬·열쇠는 그대로) |
| 한도 도달 | 설정 → 사용량에서 다시 쓸 수 있는 시각 확인. 그때까지 진행자 시연을 보거나 짝꿍 화면을 함께 봅니다 (남의 계정으로 로그인하지 않음). 다시 쓸 수 있게 되면 도전 카드는 건너뛰고, 규칙표 · 회의록 · 스킬 2개(P5-f 가능) · 직원 5명을 먼저 끝냅니다 |
